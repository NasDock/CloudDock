# 2026-10-22

## CLOSE_WAIT / fd 泄漏排查与修复

背景：server（Fastify + ws，端口 3300）出现大量 CLOSE_WAIT，fd 泄漏 + CPU 空转。

排查结论：
- 数据库侧无问题（Prisma 单例 SQLite、ioredis lazyConnect + retryStrategy:null）。
- 主要问题在 WS 会话清理和 nas-client 转发本地服务的 HTTP 请求。

已修复：
1. `server/src/gateway/connection-pool.ts` — 心跳判定死亡时只 removeConnection 从不关 socket，改为 `ws.terminate()`；removeConnection 增加兜底 terminate。
2. `server/src/gateway/ws-heartbeat.ts` — 超时时用 `ws.close(1006)`（1006 是保留码不能发送，关闭失效），改为 `ws.terminate()`。
3. `nas-client/src/client.ts` forwardHttpToLocal — 剥离 connection/keep-alive 等逐跳头、`agent: false`、30s `req.setTimeout` + destroy、补 `res.on('error')`。
4. `nas-client/src/modules/http-proxy.ts` forwardToLocal — 同上处理。
5. `nas-client/src/modules/health-check.ts` — 修复 ws:// 被错转成 https:// 的协议 bug（导致每 30s 对明文 HTTP 做 TLS 握手）；catch 分支原先误判为 healthy；补 drain response body。
6. `nas-client/src/modules/proxy-server.ts` — error 路径补 `socket.destroy()`。
7. `nas-client/src/modules/tcp-relay.ts` — localSocket error 时补 destroy。

备注：工作区未安装 node_modules（npm registry 走 127.0.0.1:7890 代理但代理未开），无法本地跑 tsc 验证，改动均为标准 ws/http API 使用。
